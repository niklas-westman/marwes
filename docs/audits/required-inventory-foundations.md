## Proof and decision requirements

All families need independent structural assertions, exact-source visual evidence
where applicable, source integrity, adapter coverage and explicit owner review.
The following are proposals for behavior applicability, not approvals:

| Families                 | Proposed behavior treatment                                           | Required independent checks                                                                                                                                                                                                    |
| ------------------------ | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Text, Paragraph, Heading | Noninteractive; no action/keyboard behavior                           | Correct element, heading precedence/level, accessible naming, wrapping and typography. Noninteractive does not waive semantic accessibility.                                                                                   |
| Icon                     | Noninteractive graphic                                                | Decorative icons hidden; informative icons named with appropriate graphic role; SVG geometry, stroke and color inheritance independently verified.                                                                             |
| Spacing, Stack           | Noninteractive layout primitives                                      | Decorative spacing hidden; list/nav semantic output; sizing, wrapping, precedence and independent token math. Approve layout/token authority before visual nonapplicability is claimed.                                        |
| Divider                  | Noninteractive separator                                              | Separator role, orientation and measured occupied spacing/line geometry.                                                                                                                                                       |
| Skeleton, Spinner        | No activation behavior; motion/status proof remains required          | Decorative versus named status/live semantics, reduced-motion handling and declared animation phase/timing. Static comparison needs a deterministic approved phase.                                                            |
| Progress Bar             | Noninteractive range display; dynamic value semantics remain required | Name/reference precedence, min/max/value/value-text, disabled semantics, clamping and invalid-range behavior from the documented public contract. Hover/pressed/focus are visual API states, not evidence of user interaction. |

Before converting this brief into required contracts, resolve:

1. Text Micro and Paragraph sm/lg design authority; retain registry/type discrepancies as explicit gaps.
2. The 227-name icon/source bijection, source-only 12px and stroke/color selection authority.
3. Missing large Spacing tokens and approved independent Stack auto-layout rules.
4. Divider source-only 12/24px and public-only vertical treatment without silently changing the public API.
5. Actual Skeleton shape designs and theme/motion treatment; the empty scaffold cannot be promoted as a valid reference.
6. Progress Bar Default/Inline versus small/default and its exact state bindings.
7. A finite, documented policy for continuous/custom dimensions, numeric overrides and animation proof.
8. Adapter-specific API deltas and explicit behavior applicability records before any family is called exhaustive.

No source/reference promotion, fixture enrollment, runtime modification or machine
inventory change was performed for this research.
